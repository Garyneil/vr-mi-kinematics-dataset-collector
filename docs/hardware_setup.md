# 硬件接入与参数确认

本文档用于记录 EEG/ECG、动捕服和 VR 设备在正式实验前必须确认的信息。

## 1. EEG/ECG

当前已知：

- EEG：8 通道；
- ECG：4 通道；
- 名义采样率：250 Hz；
- 串口波特率：115200；
- 当前兼容旧版 26 字节帧和带 packet ID 的 30 字节帧。

正式采集前仍需确认：

- EEG 电极位置；
- 参考电极；
- 地电极；
- ADC 分辨率；
- 放大倍数；
- 原始整数到微伏的换算关系；
- 硬件滤波参数；
- ECG 导联方式；
- 电气隔离方式；
- 设备端是否支持 packet ID、设备时间戳和 CRC。

## 2. 动捕服

正式接入前需确认：

- 品牌和型号；
- 厂商软件版本；
- SDK 名称和版本；
- Windows、Linux 或 Jetson 支持情况；
- 数据输出方式：UDP、TCP、OSC、共享内存、CSV 或 SDK；
- 实时采样率；
- 是否包含设备时间戳和 frame ID；
- 坐标系方向；
- 位置单位；
- 姿态格式：欧拉角、四元数或旋转矩阵；
- 骨架节点名称；
- 是否提供手指关节；
- 丢帧检测方法。

建议至少保留以下上肢节点：

```text
pelvis
spine
chest
left_shoulder
left_elbow
left_wrist
left_hand
right_shoulder
right_elbow
right_wrist
right_hand
```

如果动作主要由单侧手完成，仍建议保留躯干和双侧上肢，用于检测身体代偿和非目标动作。

## 3. VR

正式接入前需确认：

- VR 头显品牌和型号；
- 是否使用控制器；
- 开发引擎：Unity、Unreal 或其他；
- 帧率和刷新率；
- VR 程序运行主机；
- 与采集程序的事件通信方式；
- cue、任务开始、反馈开始和 trial 结束事件格式；
- VR 时间戳来源；
- 是否能记录头显和控制器位姿。

## 4. 同步原则

优先级从高到低：

1. 设备硬件触发或共享硬件时钟；
2. 设备端时间戳与 packet/frame ID；
3. 同一主机上的单调时钟；
4. 网络接收时间。

论文正式采集不建议只依赖普通系统时间和手工对齐。

建议每类数据至少保存：

```text
host_timestamp
设备时间戳（若有）
packet_id 或 frame_id
session_id
block_id
trial_id
stage
task
事件名称
```

## 5. 运动想象阶段的静止检测

动捕服可以在运动想象阶段用于质量控制，而不是作为 EEG 解码输入。

后续可根据数据分布设定：

- 手部最大位移阈值；
- 腕部最大速度阈值；
- 肘关节角变化阈值；
- 躯干位移阈值。

阈值不能在没有预实验数据的情况下任意写死。建议先采集若干静息和运动想象试次，再根据噪声水平和自然姿态漂移确定。

## 6. 当前代码状态

当前仓库已提供：

- EEG/ECG 串口读取；
- 四任务三阶段协议；
- 通用动捕抽象接口；
- 通用 UDP JSON 动捕适配器骨架；
- 实验事件和元数据记录框架。

尚未完成：

- 具体厂商动捕 SDK 接入；
- Unity/Unreal VR 事件发送端；
- 硬件触发同步；
- 真实动捕字段映射；
- 基于预实验数据的动作污染阈值。

这些内容需要在设备参数确认后补充。
